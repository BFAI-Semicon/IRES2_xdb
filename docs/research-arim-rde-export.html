1結論

プログラムから直接は送れない

外部システム向けのデータ登録 API は公開されていない。ログインもブラウザ画面が前提で、システムが人の代わりに入る正規の手段はない。

アカウントは個人の DICE アカウント

登録する人ごとに DICE アカウントが必要。システム用の共通アカウントや API キーの仕組みはない。

現実的な送り方は「ファイルを作って、人が画面から登録」

本システムが RDE の一括登録形式（ExcelInvoice）のファイルを作り、ユーザーが RDE の Web 画面でアップロードする方法が、公式に支えられた唯一の準自動化。

2用語を整理

ARIM
マテリアル先端リサーチインフラ事業。全国の共用装置を使い、得たデータを登録することが求められる国の事業。
RDE
Research Data Express。NIMS（物質・材料研究機構）が運営する、実験データを登録・保管する Web システム。ARIM のデータの送り先。
DICE
NIMS のデータ基盤サービスの総称。RDE を使うためのアカウントは「DICE アカウント」と呼ぶ。
センターハブ
ARIM 事業の中核を担う NIMS 側の組織。RDE の運用や一括登録の作業を担う。
研究チーム
RDE 上で課題番号に紐づくメンバーの集まり。データ登録の権限はこの単位で決まる。
データセット
RDE で複数のデータをまとめる箱。装置ごと・課題ごとに開設される。本システムの「実験データ」は RDE の「データ」1 件に相当する。
データセットテンプレート
データセットごとに決まる「入力欄の定義」と「登録後の自動処理」のセット。装置担当が用意する。
送り状
RDE でデータを 1 件登録するときに入力する伝票のような画面。基本情報・試料情報・固有情報・ファイルから成る。
ExcelInvoice
送り状の内容を Excel の表にまとめ、多数のデータを 1 回の操作で登録する RDE の機能。
DICE ID（UUID）
RDE 内部でユーザーを識別する長い英数字の ID。ExcelInvoice ではメールアドレスではなくこの ID で人を指定する。

3アカウント ― 誰が登録できるのか

RDE にデータを登録するには、登録する人本人の DICE アカウントが必要。ID はメールアドレス。

メールアドレスの条件 所属機関から支給されたメールアドレスのみ使える。Gmail などのフリーメールは不可。ARIM の利用申請で使ったアドレスと同じものでなければならない。

アカウントが使えるようになるまでの流れ

ARIM 利用申請システムでユーザー登録所属機関のメールアドレスで
DICE アカウントを作成データ提供「あり」の場合に必要
利用申請し、課題が採択される課題番号が付く
研究チームに課題番号を紐付け機関のスタッフが行う
データセットを開設装置ごと
データ登録ここから送出できる

研究チームの中の役割と、できること

同じ研究チームでも、役割によってできることが違う。データを登録できるのは 4 つの役割。

役割RDE 上の名前データ登録閲覧・ダウンロード削除
研究チーム管理者OWNERできるできるできる
管理者代理ASSISTANTできるできるできる
研究チームメンバMEMBERできるできるできない
データ登録代行者AGENTできるできないできない
データ閲覧者VIEWERできないできるできない
  • 「データ所有者」「試料管理者」は役割ではなく、データに付ける属性。持っていても権限は増えない。
  • ARIM のスタッフは「登録代行」はできるが、登録されたデータを見たり直したりはできない。
  • ExcelInvoice で人を指定するときは DICE ID（UUID）を使う。RDE 閲覧アプリで自分の名前をクリックしたときの URL の users/ 以降の文字列がそれ。

4ログイン ― どう入るのか

RDE には「データ登録アプリ」と「データ閲覧アプリ」があり、URL が違う。どちらもブラウザから入る。

ログインの手順

RDE のアプリを開くChrome / Edge / Firefox / Safari の最新版
メールアドレスを入力
「DICE アカウントでログイン」を選ぶ「NIMS アカウント」は NIMS 内ネットワーク限定
パスワードを入力

パスワードの決まり

英大文字・英小文字・数字・記号の 4 種類をすべて含み、10 文字以上。間違え続けると 30 分ロックされる。

多要素認証（MFA）

スマートフォンの認証アプリ、またはメールで届くワンタイムパスワードを追加できる。今は任意だが、2026 年 4 月に「強く推奨」と告知された。将来必須になる可能性がある。

ログインの有効時間

内部のトークンは 1 時間で切れるが、ブラウザを開いていれば自動で延長され、その日のうちは使い続けられる。

本システムにとっての意味 ログインの仕組み（認証プロトコル）や、外部システムを登録して連携する方法は公開されていない。つまり、本システムがユーザーの代わりにログインして RDE に入る正規の方法はない。ユーザーのパスワードを預かって画面を自動操作する方法は、規約違反や MFA で動かなくなるリスクがあり、採るべきではない。

5API ― プログラムから自動で送れるのか

結論: 外部から使えるデータ登録 API はない 公式サイト、ARIM の手引き、RDEToolKit の説明書、RDE の論文のいずれにも記載がない。内部向けの API（「Sample API」）への言及はあるが、仕様も認証方法も公開されていない。

よくある誤解: RDEToolKit で送れるのでは？

RDEToolKit は NIMS が公開している Python のライブラリだが、これは RDE の中で動く自動処理（データセットテンプレート）を作るための道具であり、データを RDE に送る機能は持たない。手元で動かせるのは、登録前にファイルの形式を確認する目的にとどまる。

一括登録はできるのか（公式 FAQ より）

  • 決められた形式に揃えれば、一括登録できる仕組み自体はある。
  • ただし、ユーザーや各機関の技術スタッフが自分で行うことはできず、センターハブのシステムエンジニアに依頼する形になる。
  • 事前にセンターハブと技術的な確認を行い、データを整える処理（構造化スクリプト）を作る必要がある。
  • 試験用の環境もセンターハブしか使えない。

公式に使える準自動化: ExcelInvoice モード 利用可

「Excel の 1 行 = データ 1 件」として表を作り、登録するファイルを zip にまとめ、1 回のアップロード操作で多数のデータを登録できる機能。

用意するもの

  • ファイル名が _excel_invoice.xlsx で終わる Excel
  • 登録するデータファイルを入れた zip

前提と注意

  • 送り先データセットのテンプレートが ExcelInvoice に対応している必要がある（装置担当が用意）
  • 人は DICE ID（UUID）、既存の試料は試料 UUID で指定。合わないと登録エラー

上限

  • 1 ファイルあたり 2 GB
  • ファイル数は無制限

登録した後の流れ

受付完了→ データ構造化開始→ 正常終了または異常終了

自動で通知は来ない。RDE の画面を更新して自分で確認する。ブラウザを閉じても処理はサーバー側で続く。

6登録時に入力するもの（送り状）

データ 1 件ごとに、次の 4 つのまとまりを入力する。本システムから送るときは、これらを埋められる情報を持っておく必要がある。

まとまり項目
基本情報 記入年月日（自動）、データ投入者（ログインした人が自動で入る）、データ名（必須）、実験 ID、説明、装置（必須）、データ所有者
試料情報 試料名（ローカル ID）、化学式・組成式・分子式、参考 URL、タグ、試料の説明、試料管理者
固有情報 装置ごとに違う手入力の項目。定義ファイル invoice.schema.json で決まり、必須項目があることもある
ファイル データファイル（装置ごとに決まった拡張子。RDE が自動処理する対象）、添付ファイル（任意）

本システムの用語との対応: 本システムの「実験データ」= RDE の「データ」1 件、「固有情報」= 固有情報、「試料」= 試料情報、「添付」= 添付ファイル。

7本システムはどう送るべきか

案 A. 送出パッケージを作る 推奨

本システムが ExcelInvoice 形式の Excel と zip を作る。ユーザーはそれを RDE の画面からアップロードする。

良い点: RDE が公式に支える方法の範囲内。ログインは RDE 側の画面で済むため、本システムがパスワードを扱わない。

案 B. ブラウザを自動操作する 非推奨

ユーザーの DICE の ID・パスワードを本システムが預かり、画面操作をプログラムで再現する。

問題点: 利用規約に抵触するおそれ。MFA が必須化されると動かなくなる。RDE の画面が変わるたびに壊れる。

案 C. 正式な連携を依頼する 並行して進める

センターハブや装置担当に、一括登録や API 連携ができないか相談する。

位置づけ: 実現すれば案 A より楽になるが、可否と時期は相手次第。案 A を進めながら問い合わせる。

案 A を採る場合、本システム側で持つ必要があるもの

  • 送出プロファイル: 課題番号（JPMXP12 から始まる 15 桁）、送り先データセット、ユーザーの DICE ID（UUID）、試料と試料 UUID の対応表
  • 固有情報の写像: 装置ごとの invoice.schema.json を装置担当から入手し、本システムの固有情報欄と項目を対応づける
  • 送出結果の記録: RDE から自動で結果は返らないため、ユーザーが RDE 画面で「正常終了」を確認し、本システムに記録する半自動の形になる
  • 設計上の変化: 当初候補だった「外部認証・送出ジョブ」の仕組みは不要になる見込み（認証は RDE 側の画面で完結する）

8確認が必要なこと

装置担当またはセンターハブに問い合わせて確定させる項目。

確認事項確定しないと困ること
対象装置のデータセットテンプレートが ExcelInvoice に対応しているか対応していなければ案 A が成り立たず、1 件ずつ画面入力になる
半導体製造装置・検査装置の登録ファイル形式（RDE が処理する拡張子）本システムから出すファイルの形が決められない
一括登録の依頼を受け付けてもらえるか、どれくらい時間がかかるか案 C の見込みが立たない
