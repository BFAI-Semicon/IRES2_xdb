# ARIM RDE 送出調査

調査日: 2026-09-02  
対象: ARIM RDE（Research Data Express）へ実験データを送出する際のアカウント・認証・API の可否  
参照: `.kiro/specs/arim-rde-export/brief.md`、`CONTEXT.md`

## 結論

- 登録には個人の DICE アカウントが必須。サービスアカウントや API キーの仕組みは公開されていない
- ログインはブラウザ前提。外部向けのデータ登録 API は存在せず、公式に使える準自動化手段は ExcelInvoice モードのみ
- 送出は「本システムが送出パッケージを生成し、ユーザーが RDE の Web 画面で登録」が現実的

## アカウント

DICE は NIMS のデータ基盤の共通アカウント。ID はメールアドレス。

- 所属機関のメールアドレスのみ可。フリーメールは不可
- ARIM 利用申請システムのユーザー登録と同一のメールアドレスであること
- 発行の流れ: ARIM ユーザー登録、DICE アカウント作成（データ提供ありの場合）、利用申請・課題採択、
  研究チームへの課題番号の紐付け、データセット開設、データ登録の順
- 登録時のユーザー識別子は DICE ID（UUID）。RDE 閲覧アプリのユーザー情報 URL の `users/` 以降で確認

### 研究チームのロール

| ロール           | CSV 値    | データ登録 | 閲覧・DL | 削除 |
| ---------------- | --------- | ---------- | -------- | ---- |
| 研究チーム管理者 | OWNER     | 可         | 可       | 可   |
| 管理者代理       | ASSISTANT | 可         | 可       | 可   |
| 研究チームメンバ | MEMBER    | 可         | 可       | 不可 |
| データ登録代行者 | AGENT     | 可         | 不可     | 不可 |
| データ閲覧者     | VIEWER    | 不可       | 可       | 不可 |

「データ所有者」「試料管理者」はロールではなく属性であり、権限は付与されない。ARIM スタッフは登録代行ができるが、登録後のデータの閲覧・編集はできない。

## ログイン認証

- 登録アプリと閲覧アプリは URL が異なる（参考リンク参照）。ブラウザで利用（Chrome / Edge / Firefox / Safari 最新版）
- 手順: メールアドレス入力、「DICE アカウントでログイン」の選択、パスワード入力。「NIMS アカウント」は NIMS 内ネットワーク限定
- パスワード: 英大文字・英小文字・数字・記号の 4 種混在、10 文字以上。連続失敗で 30 分ロック
- 多要素認証（認証アプリ OTP またはメール OTP）は任意。2026 年 4 月に「強く推奨」と告知され、必須化の可能性あり
- セッション: トークン有効 1 時間。ブラウザを開いていれば延長され、当日中有効
- 認証プロトコルや外部クライアント登録の仕様は非公開。外部システムがユーザーの代理で正規にログインする手段はない

## API からの送信

- 外部システム向けのデータ登録 API は、公式サイト・手引き・RDEToolKit ドキュメント・論文のいずれにも記載がない。
  送り状スキーマの説明に内部の「Sample API」への言及があるが、仕様と認証方法は非公開
- RDEToolKit は、RDE 側のコンテナで動く構造化処理（データセットテンプレート）を Python で書くためのライブラリ。
  `invoice.json` の生成と検証はできるが、RDE への送信はしない。ローカル実行は開発・検証用途

### 一括登録の扱い（公式 FAQ）

- 所定の形式であれば一括登録できる仕様はある
- ただし、ユーザーや各機関の技術スタッフは作業できず、センターハブのシステムエンジニアへの依頼となる
- 事前にセンターハブとの技術確認と、構造化スクリプトの作成が必要。テスト環境もセンターハブのみが利用可能

### ExcelInvoice モード（1 回の Web 登録操作で Excel 1 行 = 1 データを一括登録）

- `*_excel_invoice.xlsx` と登録ファイルの zip をブラウザからアップロード
- 前提: 登録先データセットのテンプレートが ExcelInvoice に対応していること（テンプレートは装置担当が用意）
- データ所有者・試料管理者は DICE ID（UUID）、既存試料の参照は試料 UUID で指定。不一致は登録エラー
- 制限: 1 ファイル 2 GB、ファイル数は無制限
- 登録後のステータスは「受付完了、データ構造化開始、正常終了または異常終了」と遷移。自動通知はなく、画面更新で確認

### 送り状の入力項目（1 データあたり）

- 基本情報: 記入年月日（自動）、データ投入者（ログインユーザー）、データ名（必須）、実験 ID、説明、装置（必須）、データ所有者
- 試料情報: 試料名（ローカル ID）、化学式・組成式・分子式、参考 URL、タグ、試料の説明、試料管理者
- 固有情報: テンプレートの `invoice.schema.json` に従う。必須項目あり
- データファイル（構造化対象。装置ごとに拡張子指定）、添付ファイル（任意）

## 本プロジェクトへの示唆

| 案                    | 内容                                               | 評価                              |
| --------------------- | -------------------------------------------------- | --------------------------------- |
| A. 送出パッケージ生成 | ExcelInvoice（xlsx + zip）を生成し、RDE 画面で登録 | 推奨。公式サポート内              |
| B. ブラウザ自動操作   | ユーザーの DICE 資格情報で画面操作を自動化         | 非推奨。規約・MFA・画面変更リスク |
| C. 正式連携の依頼     | センターハブ・装置担当に一括登録や API 連携を協議  | A と並行して問い合わせる          |

### 案 A で本システム側に必要となるもの

- 課題（課題番号 JPMXP12 から始まる 15 桁、期間）と装置ごとのデータセットを、グループの下で管理
- ユーザーの DICE ID（任意項目、後から追記可）。実験データ・試料には持たせず送出時にユーザーから引く
- 試料への RDE 試料 UUID の記録（初回送出後）
- 装置ごとの `invoice.schema.json` を装置担当から入手し、本システムの固有情報欄と写像
- 送出結果の記録は、ユーザーが RDE 側の完了を確認して本システムに記録する半自動の設計
- brief の境界候補「外部認証・送出ジョブ」は不要になる見込み（認証は RDE 側の画面で完結）

### 本システムとの対応表

| ARIM RDE                             | 本システム                                                                 |
| ------------------------------------ | -------------------------------------------------------------------------- |
| 課題（課題番号）                     | 課題。グループに属し、期間とデータセットを持つ                             |
| 研究チーム                           | グループ。1:1 ではなく、グループが課題を 0 個以上持つ                      |
| データセット                         | 課題の下に装置ごとに置く                                                   |
| 研究チーム管理者（OWNER）            | グループ担当                                                               |
| 研究チームメンバ（MEMBER）           | ユーザー                                                                   |
| 管理者代理・データ登録代行者・閲覧者 | 持たない。必要なら RDE 側で設定。代行登録はデータ所有者 ≠ 登録者で表す     |
| DICE ID                              | ユーザーの任意項目。送出時にユーザーから引く                               |
| データ（1 件、試料 1 つ）            | 実験データ（1 件、試料 1 つ）                                              |
| データ投入者                         | 送出したユーザー（送出記録）                                               |
| データ所有者                         | 実験データの属性（ユーザー参照、既定は登録者、権限なし）                   |
| データ名                             | 持たない。送出時に装置・試料名・実施日時から生成                           |
| 実験 ID                              | 本システムの実験データ識別子                                               |
| 説明                                 | 実験データの任意項目                                                       |
| 装置                                 | 装置台帳の装置。RDE 側の装置識別子・テンプレートを持てる                   |
| 試料（試料 UUID）                    | 試料。初回送出後に UUID を記録                                             |
| 試料名（ローカル ID）                | 試料名（グループ内で一意）                                                 |
| 試料管理者                           | 試料の属性（ユーザー参照、既定は作成者、権限なし）                         |
| 参考 URL・タグ・試料の説明           | 試料の任意項目                                                             |
| 固有情報                             | 固有情報（欄は装置担当が定義）                                             |
| データファイル・添付ファイル         | データファイル・添付（ファイルごとに区分）                                 |
| 記入年月日                           | 持たない（実施日時とは別）                                                 |
| 削除（OWNER・ASSISTANT 可）          | システム管理者のみ。意図的に厳しくしている                                 |

## 未確定事項（装置担当・センターハブへ確認）

- 対象装置のデータセットテンプレートが ExcelInvoice に対応しているか
- 半導体製造装置・検査装置の登録ファイル形式（構造化対象の拡張子）
- 一括登録依頼の受付可否と所要期間
- 試料名（ローカル ID）が一意である範囲（研究チームか、データセットか）。本システムのグループと研究チームがずれた場合の試料の重複に関わる
