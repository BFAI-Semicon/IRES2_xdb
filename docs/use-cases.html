1全体像

本システムは、オンラインに繋がらない装置の前で行った 1 操作を「実験データ」1 件として登録し、正式な記録（正本）として保管する。ARIM RDE への送出は、登録した後に行う別の段階。

フェーズ1 登録試料を作り、装置を選び、実験データを本システムに残す。訂正と検索もここに含む
フェーズ2 送出登録済みの実験データを選び、ARIM RDE へ送出
フェーズ3 入力拡張OCR（撮影した画像からの読み取り）と API（外部システムからの登録）。フェーズ2 と順序は問わない
この資料の使い方 各ユースケース（UC）に「確認したいこと」を付けている。現場の実態と合っているか、開発前にこの項目を確かめる。

2ロール ― だれが何をするか

ロールだれかできること
ユーザー 装置の前で記録を残す人 試料の作成・編集、実験データの登録、自分が登録した実験データの訂正
装置担当 ユーザーが持つ役割 全装置の固有情報欄を定義、装置台帳を管理。値の入力はユーザーとして行う
グループ担当 ユーザーが持つ、グループごとの役割 グループのメンバーの追加・除外、グループの削除
システム管理者 本システムの運用者 ユーザー・グループ・試料・実験データの削除
役割の重なり 装置担当・グループ担当は、いずれもユーザーが追加で持つ役割。ユーザーでない装置担当・グループ担当はいない。システム管理者はユーザーではなく、記録は残さない。

3グループ ― 記録をまとめる範囲

グループとは

ユーザーが属する、本システムのまとまり。大学の研究室や企業の部署を想定。ユーザーは複数のグループに属せる。

試料との関係

試料はグループに属する。試料名が一意である範囲もグループ。

実験データ・装置との関係

実験データはグループを持たない（属するグループは試料から決まる）。装置はグループに属さず、システム全体で 1 つの台帳。

ARIM RDE の「所属」とは別

ARIM RDE の所属（organization）は、データ所有者や試料管理者の機関名。本システムのグループとは別の概念。

4用語

ARIM RDE と同じ項目は ARIM RDE と同じ名称を使う。例外として、ARIM RDE の登録単位「データ」は本システムでは「実験データ」と呼ぶ。

実験データ
装置 1 台・1 操作の記録であり、登録の単位。ARIM RDE の「データ」1 件に対応。
登録
本システムの正本に実験データが残り、後から直せる状態になること。ARIM RDE への送出は含まない。
正本
記録の正式な置き場所。本システムが正本で、ARIM RDE は後から出す先。
試料
グループに属する実体で、実験データが指す対象。ARIM RDE の試料に対応。
試料名
ユーザーにとっての試料の識別子。同じグループ内で一意。
化学式・組成式・分子式
試料に属する組成。空欄でも登録可。
装置
製造装置または検査装置。実験データが指す機械。
製造装置
試料の状態を変える装置（成膜、エッチングなど）。
検査装置
試料を観察・測定する装置（顕微鏡、膜厚計など）。
装置台帳
本システムに登録された装置の一覧。システム全体で 1 つ。
固有情報
実験データに属する、その装置用のパラメータ（温度、圧力、測定条件など）。欄は装置担当が定義し、値はユーザーが入力。
添付
実験データに任意で付くファイル（ログ、写真など）。
実施日時
その操作を行った時。登録した時とは別。
訂正履歴
実験データまたは試料の過去の値の記録。最新の値が現在の内容として見える。
データセット
ARIM RDE で複数のデータをまとめる単位。送出時に課題番号などの情報が必要。

5フェーズ1に共通する決まり

本システムが正本

本システムに登録した実験データが正式な記録。ARIM RDE は後から送る先。

実験データは削除しない

登録した実験データは削除できない。誤りは訂正で直す。失敗・中断・やり直しも同じように登録。

訂正すると履歴が残る

訂正後は最新の内容が正式な記録。前の内容は訂正履歴に残る。

試料とグループ

試料は 1 つのグループに属する。実験データは 1 つまたは複数の試料を指定可。複数指定するときは同じグループの試料だけ。

空欄でも登録可

固有情報と添付ファイルは空欄でも登録可。

6フェーズ1 ― 本システムへの登録

ユーザーが装置の前で実験データを本システムに残すまでの場面。

UC-01グループに所属する ユーザー

すること
1 つ以上のグループに所属し、試料作成時にグループを選択。
確認したいこと
  • グループの単位は研究室か、部署か、別の区切りか
  • メンバーの追加や除外をだれが行うか。仮説: 「グループ担当」の役割を持つユーザーが行い、各グループに 1 人以上置く
  • グループを作ったユーザーが最初の担当。最後の 1 人は除外も辞退もできない（退職・卒業時は先に後任を指名）という運用で問題ないか

UC-02試料を作る ユーザー

すること
グループを選び、試料名を付けて試料を作成。化学式・組成式・分子式は空欄でも可。
前提
同一グループ内における試料名は一意。
確認したいこと
  • 現場で使っている試料名の付け方
  • 組成は試料作成時に必須か、後から入力でもよいか

UC-03試料の内容を直す ユーザー

だれが
その試料を作ったユーザー、またはその試料を使って実験データを登録したユーザー。
すること
試料の組成や名称などの誤りを訂正。
確認したいこと
  • 「作った人と使った人だけが直せる」で現場は足りるか
  • 同じグループの他のユーザーにも訂正を許したい場面があるか

UC-04装置を台帳に登録する 装置担当

すること
製造装置か検査装置かを決めて、装置を台帳に登録。
前提
台帳はシステム全体で 1 つ。1 台の装置は主な用途でどちらか一方の種別。
確認したいこと
  • 装置の追加、名称変更、使用終了を装置担当が行う形で問題ないか
  • 現場で通じる装置の呼び名（装置に貼ってあるラベルなど）

UC-05固有情報の欄を決める 装置担当

すること
装置ごとに、記録しておきたい項目（固有情報の欄）を定義。
前提
ユーザーが入力するのは欄の値だけ。欄そのものは作らない。
確認したいこと
  • どの装置でどんな欄が必要か（温度、圧力、膜厚、測定条件など）
  • 欄を変更する頻度と、変更前に登録した実験データの見せ方
  • 装置担当が全装置の欄を決める形で問題ないか

UC-06製造の実験データを登録する ユーザー

すること
製造装置、試料（1 つ以上）、実施日時を選び、固有情報と添付ファイルを入力して登録。
前提
失敗、中断、やり直しも同じように登録。
確認したいこと
  • どこまでを 1 件の実験データとして扱うか（装置 1 台の 1 操作という区切りで合うか）
  • 実施日時は装置の表示、手元のメモ、登録した時刻のどれを使うか
  • 固有情報を入力せずに登録する場面があるか

UC-07検査の実験データを登録する ユーザー

すること
UC-06 と同じ手順で、検査装置での作業を登録。
前提
同じ試料について、製造のあとに検査の実験データを続けて登録可。
確認したいこと
  • 製造と検査で、入力してもらう項目に違いを付けたいか
  • 1 つの試料に対する製造と検査のおおよその回数

UC-08ファイルを添付する ユーザー

すること
実験データの登録時や訂正時に、ログや写真などのファイルを添付。
確認したいこと
  • よく添付するファイルの種類とおおよその大きさ
  • ARIM RDE に送るときの必須ファイルと、この添付を分けて考えられるか

UC-09実験データを訂正する ユーザー

だれが
その実験データを登録したユーザーだけ。
すること
入力を間違えた実験データの内容を訂正。
確認したいこと
  • 登録した本人以外が代わりに直す必要があるか
  • 添付ファイルの差し替えや追加も訂正として扱うか

UC-10過去の記録を見る ユーザー

だれが
ユーザー（見られる範囲は確認したい）。
すること
試料、装置、実施日などで検索し、最新の内容と訂正履歴を確認。
確認したいこと
  • 他のグループの記録を見られてよいか
  • よく使う検索の仕方（試料名、装置、実施日、登録したユーザーなど）

7フェーズ2–3 ― 送出・入力拡張

いずれも登録（フェーズ1）の後に行う。OCR と API はどちらを先にしてもよい。

UC-11ARIM RDE へ送出する ユーザー

だれが
ユーザー（送出を担当するユーザーを含む）。
すること
送る実験データを選び、データセットの情報（課題番号など）を添えて送出。
前提
送出したあとも、正式な記録は本システムのまま。
確認したいこと
  • 送出のタイミング（その日のうち、週に 1 度、論文の前など）
  • 1 回の送出でまとめる単位（データセット）の決め方
  • 送出に失敗したとき、現場でどう分かるとよいか

UC-12OCR で登録する ユーザー

すること
装置のパネルや紙のノートを撮影し、読み取り結果を確認・補正して登録。
確認したいこと
  • 撮影する対象は装置のパネルか、紙のノートか、両方か
  • 読み取り結果はユーザーが必ず確認する前提でよいか

UC-13API で登録する 外部システム

だれが
連携する外部システム（ユーザーは間接的に関わる）。
すること
API から実験データを登録。
前提
権限や訂正の決まりは手入力と同じ。
確認したいこと
  • 連携したい装置やソフトがあるか、その優先度
  • API から登録した場合、登録したユーザーをどう特定するか

8対象外

本システムでは次の機能を扱わない。

装置予約

稼働見える化

映像化・画像解析

施設・工程の管理

ユーザーによる実験データの削除

確認したいこと 対象外のうち、現場で「必須」となるものがないか。

10確認チェックリスト

セッションの最後に、次の方針に合意できたかを確認する。

  • 1 操作 = 1 実験データ。失敗・中断も登録し削除しない
  • 正本は本システム。ARIM RDE は後から送る先
  • 固有情報欄は装置担当が定義、ユーザーは値を入力
  • 実験データの訂正は登録者のみ
  • 試料編集は作成者とその試料を使ったユーザー
  • 削除は表示から隠すだけで記録は残る（ユーザー・グループ・試料・実験データ）
