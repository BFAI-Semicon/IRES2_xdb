# ユースケース フェーズ2–3 — 送出・入力拡張

全体の一覧は [use-cases.md](use-cases.md)。いずれも登録（フェーズ1）の後に行う。OCRとAPIはどちらを先にしてもよい。

## UC-11 ARIM RDE へ送出する

- だれが: DICE ID を持つユーザー
- すること: 送る実験データを選び、試料のグループが持つ課題とデータセット（装置ごと）を選ぶ。本システムが ExcelInvoice の送出パッケージ（xlsx + zip）を作り、ユーザーが RDE の画面で登録する。RDE 側の結果（データ ID、正常終了・異常終了）を本システムに記録する
- 前提:
  - 課題（課題番号・期間）とデータセットは、グループ担当が事前にグループへ登録しておく
  - 1 実験データ = RDE の 1 データ = 1 試料
  - データ所有者・試料管理者・送出者の DICE ID をユーザーから引く。未登録なら送出前に「だれの DICE ID が足りないか」を示して止める
  - データ名は装置・試料名・実施日時から生成し、実験 ID に本システムの識別子を入れる
  - 初回送出後に RDE の試料 UUID を試料に記録し、2 回目以降は既存試料として参照する
  - 送出したあとも、正式な記録は本システムのまま
- 確認したいこと:
  - 送出のタイミング（その日のうち、週に1度、論文の前など）
  - 課題とデータセットをだれが登録するか（グループ担当で合うか）
  - RDE 側の結果をだれが確認して本システムに記録するか
  - 送出に失敗したとき、現場でどう分かるとよいか

## UC-12 OCR で登録する

- だれが: ユーザー
- すること: 装置のパネルや紙のノートを撮影し、読み取り結果を確認・補正して登録
- 確認したいこと:
  - 撮影する対象は装置のパネルか、紙のノートか、両方か
  - 読み取り結果はユーザーが必ず確認する前提でよいか

## UC-13 API で登録する

- だれが: 連携する外部システム（ユーザーは間接的に関わる）
- すること: API から実験データを登録
- 前提: 権限や訂正の決まりは手入力と同じ
- 確認したいこと:
  - 連携したい装置やソフトがあるか、その優先度
  - API から登録した場合、登録したユーザーをどう特定するか
